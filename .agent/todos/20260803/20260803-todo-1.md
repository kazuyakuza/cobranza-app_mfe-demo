# Phase 0 — mfe-demo Scaffold & Contract Foundation

Goal of this phase only: Create a buildable Angular 22 remote application with Native Federation configured, the shared libraries consumed, the main exposed demo component accepting Shell Inputs, internal `DemoConfig` parsing, the default `'table'` view rendered, core `mfe:*` events dispatched (`module-ready`, `update-header`), basic identity panel + instance visual marker, and a minimal standalone preview host so the MFE can be developed and verified without the full Shell.

Explicitly out of scope for Phase 0:

- `'create-form'` and `'profile'` view bodies (stubs / “not implemented” placeholder only if needed)
- Full action button set (`show-notification`, `request-fullscreen`, `request-remove`, `request-add-module`, error simulation)
- Local event log UI
- Data payload pretty-printer beyond a simple debug line
- Full min-height event/input wiring (placeholder is enough)
- Real integration testing against a running Shell (manual smoke is fine)
- Production deploy configuration
- Unit/e2e test suite (optional; do not block the phase)

## Objective

At the end of this phase the repository must:

1. Be a clean Angular 22 application configured as a Native Federation remote.
2. Depend on and successfully import:
   - `@cobranza-apps/ui`
   - `@cobranza-apps/mfe-events`
   - `@cobranza-apps/entities` (at least as a dependency; use types if helpful for mock table rows)
3. Apply the intermediate gray theme from `@cobranza-apps/ui`.
4. Expose a single standalone component that the Shell can load (convention: remote name `mfe-demo`, exposed module `./Component` or the name agreed with the Shell’s federation config).
5. Accept the Shell Inputs: `moduleType`, `instanceId`, `size`, `isCollapsed`, `isFullscreen`, `data`.
6. Parse `data` into internal `DemoConfig` / `DemoViewMode` and default to `'table'`.
7. Render the table view (mock rows, reflows with size) plus the common identity panel and a per-instance visual marker.
8. On init / first mount: dispatch `mfe:module-ready` and `mfe:update-header` (using title from config when present).
9. Provide a minimal standalone preview page (`ng serve`) that injects mock Inputs and can switch basic config so UI work is possible without the Shell.
10. Contain a clear README explaining how to run alone and the federation identity (remote name + exposed module).

No other views or full event surface are required yet.

## Important constraints

- Standalone components only. No NgModules.
- Desktop-only. Do not add mobile breakpoints or responsive work beyond what Bootstrap already provides.
- Spanish-only UI strings.
- Prefer composition with `@cobranza-apps/ui` components and tokens over custom styling.
- Never manipulate the DOM outside the MFE’s own container.
- Never depend on Shell layout concepts (rows, drag handles, etc.).
- Do not invent features outside the project brief.
- Keep the surface small: one main exposed component; optional small view sub-components only if they improve clarity.
- Primary browser target is latest Chrome; do not block the phase on other browsers.
