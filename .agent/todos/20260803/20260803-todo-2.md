# Phase 1 — mfe-demo Views, Actions & Debug Surface

**Goal of this phase only:** Complete the three configurable views (`table`, `create-form`, `profile`), implement the full set of action buttons and remaining `mfe:*` events, add the local event log and data payload viewer, listen to the main `shell:*` events (with `instanceId` filter), and improve the standalone preview so every view and action can be exercised without the Shell.

**Explicitly out of scope for Phase 1:**

- Full min-height contract (Input/event) beyond a sensible static or simple update
- Real integration testing against a running Shell (manual smoke is still enough)
- Production deploy / CI configuration
- Unit/e2e test suite (optional; do not block the phase)
- Business domain logic or real API calls

## Objective

At the end of this phase the repository must:

1. Render all three body views according to `DemoConfig.view`:
   - `'table'` — already present from Phase 0; polish if needed
   - `'create-form'` — simulated fixed create form (no real submit)
   - `'profile'` — read-only profile / detail ficha from `config.profile` or mock defaults
2. Prefer types from `@cobranza-apps/entities` where they fit the mock data (table rows, profile fields); otherwise keep local interfaces.
3. Expose the full action button set (Spanish labels) that dispatch the corresponding `mfe:*` events:
   - Update header title/status
   - Show notification (success / warning / error)
   - Request fullscreen
   - Request remove
   - Request add another `demo` instance (with optional different `initialData` / view)
   - Optional: simulate error (`mfe:module-error`)
4. Maintain a local **event log** (last N events sent/received for this instance) visible in the UI.
5. Show a **data payload viewer** (pretty-print of the raw `data` Input).
6. Listen to at least `shell:module-state` (and optionally `shell:visibility-changed`) filtered by `instanceId`, and reflect size / collapse / fullscreen changes in the identity panel and layout.
7. Keep all content usable at both `50%` and `100%` width and in fullscreen for every view.
8. Extend the standalone preview host so the developer can switch views, inject sample `DemoConfig` values, toggle size/collapse/fullscreen mocks, and see the event log / dispatched events.

## Important constraints

- Same constraints as Phase 0 (standalone only, desktop-only, Spanish-only, no DOM outside container, no Shell layout knowledge, prefer `@cobranza-apps/ui`).
- Do not re-implement ModuleHeader, drag handle, size toggle, collapse, remove, or fullscreen chrome.
- Every outgoing `mfe:*` event must include `moduleType` + `instanceId` and use the helpers from `@cobranza-apps/mfe-events`.
- Incoming `shell:*` events must be filtered by `instanceId` (and usually `moduleType`).
- Keep the surface small; extract view sub-components only if the main template becomes hard to read.

## Preconditions (agent must verify first)

1. Phase 0 is complete: app builds, federation remote works, Inputs and `DemoConfig` exist, table view and identity panel render, `module-ready` / `update-header` dispatch.
2. Confirm the current shape of helpers/types in `@cobranza-apps/mfe-events` (especially factories for `show-notification`, `request-fullscreen`, `request-remove`, `request-add-module`, `module-error`, and any listener utilities).
3. Confirm available components from `@cobranza-apps/ui` that are useful for forms, buttons, and simple cards/lists.
4. Inspect existing `demo.component.*` and `demo-config.ts` so new code extends them instead of rewriting.

| Button (ES) | Event | Notes |

| Actualizar título / estado | `mfe:update-header` | Cycle or set a few title/status combinations for demo |
| Notificación éxito | `mfe:show-notification` | type success |
| Notificación advertencia | `mfe:show-notification` | type warning |
| Notificación error | `mfe:show-notification` | type error |
| Pedir pantalla completa | `mfe:request-fullscreen` | |
| Pedir quitar módulo | `mfe:request-remove` | |
| Agregar otra instancia demo | `mfe:request-add-module` | Prefer `moduleType: 'demo'`; may pass `initialData` with a different `view` |
| (Opcional) Simular error | `mfe:module-error` | Only if the library exposes a clear helper |

- [ ] In standalone preview, all dispatches must be visible in the console and/or the local event log.

### 6. Local event log
