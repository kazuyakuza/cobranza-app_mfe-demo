# Phase 2 — mfe-demo Polish, Min-height & Delivery

Goal of this phase only: Close the MFE as a solid reference implementation. Wire the real min-height contract via `@cobranza-apps/mfe-events@^0.6.0` (`mfe:update-min-height`), polish UX and edge cases across all views, harden multi-instance / shell-state handling (`dragState` / `previewMode`), finish agent-oriented and Shell-oriented documentation (including ready-to-copy Footer config examples), and leave the repo in a clean, hand-off-ready state. Optional light tests may be added but must not block delivery.

Shared lib targets (verify at start of phase):

| Package | Target | Notes |
| --------- | -------- | -------- |
| `@cobranza-apps/mfe-events` | ^0.6.0 | Adds `MFE_EVENTS.UPDATE_MIN_HEIGHT` / `UpdateMinHeightPayload` |
| `@cobranza-apps/ui` | ^0.19.0 | Minimal Yet Warm theme; `Cba*` components |
| `@cobranza-apps/entities` | ^0.5.1 | Domain field names for mocks/forms (plain `string` in UI) |

Explicitly out of scope for Phase 2:

- Real BFF / API calls or business domain logic
- Production deploy pipelines / CI (document only if trivial)
- Becoming a shared library that other MFEs import
- Changes to `@cobranza-apps/mfe-events`, `@cobranza-apps/ui`, or `@cobranza-apps/entities`
- Mobile layout or i18n
- Full automated e2e against a live Shell (manual integration notes are enough)
- Implementing the Shell-side listener for `mfe:update-min-height` (Shell owns that; demo only emits)

## Objective

At the end of this phase the repository must:

1. Depend on `@cobranza-apps/mfe-events@^0.6.0` and dispatch `mfe:update-min-height` (`MFE_EVENTS.UPDATE_MIN_HEIGHT`) on init and when the active view / content needs change, with a sensible `minHeightPx` per view.
2. Show the last declared `minHeightPx` in the identity panel (and standalone preview controls).
3. Behave correctly under collapse, size toggle, fullscreen, and multi-instance without visual breakage or event leakage between instances.
4. Optionally surface `dragState` / `previewMode` from `shell:module-state` in the identity panel or event log.
5. Have polished, consistent Spanish UI copy and layout across identity panel, action bar, three views, event log, and data viewer.
6. Ship complete documentation aimed at:
   - Developers / AI agents implementing or extending the MFE
   - Shell developers configuring Footer entries and testing workspace features (including min-height)
7. Include ready-to-copy Footer / `DemoConfig` examples for the three views.
8. Leave README + docs accurate, linked, and sufficient for hand-off.
9. Pass a final manual verification checklist (standalone + notes for Shell integration).

Optional: a small set of unit tests for pure helpers (config parsing, instance colour hash, event filter, min-height computation) — nice to have, not required for DoD.

## Important constraints

- Same constraints as previous phases (standalone only, desktop-only, Spanish-only, no DOM outside container, no Shell layout knowledge, prefer `@cobranza-apps/ui`).
- Do not invent events outside `@cobranza-apps/mfe-events`. Use only catalog constants (`MFE_EVENTS` / `SHELL_EVENTS`).
- Min-height is a layout preference, not an exact height command. Never invent `mfe:set-height`. Never treat `shell:module-state.height` as the MFE-declared minimum (that field is the current container height from the Shell).
- Every outgoing `mfe:*` payload must include `schemaVersion: SCHEMA_VERSION` and the required identity fields.
- `reflect-metadata` remains a peer of `mfe-events`: load it via the Angular builder `scripts` array (`node_modules/reflect-metadata/Reflect.js`), not via ESM `import 'reflect-metadata'` in the app entry.
- Keep the demo honest: it is a test harness / reference, not production company UI.
